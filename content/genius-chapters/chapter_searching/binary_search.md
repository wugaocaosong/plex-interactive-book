# 二分查找

![搜索](/genius/media/image_224.jpeg)

Abstract

搜索是一场未知的冒险，我们或许需要走遍神秘空间的每个角落，又或许可以快速锁定目标。

在这场寻觅之旅中，每一次探索都可能得到一个未曾料想的答案。

二分查找（binary search）是一种基于分治策略的高效搜索算法。它利用数据的有序性，每轮把搜索范围砍掉一半，直到找到目标元素，或者搜索区间变空为止。

Question

给定长度为 $n$ 的数组 nums ，元素从小到大排好且不重复。请找出元素 target 在数组里的索引并返回；数组里没有这个元素就返回 $−1$ 。示例如下图。

![二分查找示例数据](/genius/media/image_225.png)

如下图所示，我们先初始化指针 $i=0$ 和 $j=n−1$ ，分别指向数组首元素和尾元素，代表搜索区间 $[0,n−1]$ 。请注意，中括号表示闭区间，其包含边界值本身。

接下来，循环执行以下两步。

1. 先算中点索引 $m=⌊(i+j)/2⌋$ ，其中 $⌊ ⌋$ 表示向下取整。

1. 再拿 nums[m] 和 target 比大小，分三种情况。

    1. nums[m] < target 时，说明 target 在区间 $[m+1,j]$ 里，于是执行 $i=m+1$ 。

    1. nums[m] > target 时，说明 target 在区间 $[i,m−1]$ 里，于是执行 $j=m−1$ 。

    1. nums[m] = target 时，说明找到了，返回索引 $m$ 。

如果数组里没有目标元素，搜索区间最后会缩成空，这时返回 $−1$ 。

值得注意的是，由于 $i$ 和 $j$ 都是 int 类型，因此 $i+j$ 可能会超出 int 类型的取值范围。为了避免大数越界，我们通常采用公式 $m=⌊i+(j−i)/2⌋$ 来计算中点。

时间复杂度为 $O(logn)$ ：二分循环里区间每轮缩小一半，所以循环次数是 $log_{2}n$ 。

空间复杂度为 $O(1)$ ：指针 $i$ 和 $j$ 使用常数大小空间。

## 区间表示方法

除了双闭区间，常见的还有“左闭右开”区间，定义为 $[0,n)$ ，左边界包含自身、右边界不包含自身。这种写法下，区间 $[i,j)$ 在 $i=j$ 时为空。

由于“双闭区间”表示中的左右边界都被定义为闭区间，因此通过指针 $i$ 和指针 $j$ 缩小区间的操作也是对称的。这样更不容易出错，因此一般建议采用“双闭区间”的写法。

## 优点与局限性

二分查找在时间和空间上的表现都不错。

- 时间效率高：数据量大时，对数级的时间复杂度优势很明显。比如数据规模 $n=2^{20}$ 时，线性查找要循环 $2^{20}=1048576$ 轮，二分查找只要 $log_{2}2^{20}=20$ 轮。

- 不占额外空间：和需要额外空间的搜索算法（比如哈希查找）相比，二分查找更省内存。

不过二分查找也不是万能的，主要有下面几个原因。

- 只适合有序数据。如果数据本来就无序，为了用二分查找专门排一次序并不划算：排序的时间复杂度通常是 $O(nlogn)$ ，比线性查找和二分查找都高。而对经常插入元素的场景，为了保持数组有序，插入时得把元素放到指定位置，时间复杂度是 $O(n)$ ，也很贵。

- 只适合数组。二分查找需要跳着（非连续地）访问元素，链表做这种跳访效率很低，所以链表或基于链表实现的结构都不适合。

- 数据量小的时候，线性查找反而更好。线性查找每轮只做 1 次判断；二分查找每轮要做 1 次加法、1 次除法、1～3 次判断、1 次加法（减法），一共 4～6 个基本操作。所以数据量 $n$ 不大时，线性查找比二分查找还快。
