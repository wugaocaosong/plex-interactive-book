# 哈希优化策略

做算法题时，我们常通过将线性查找替换为哈希查找来降低算法的时间复杂度。下面用一个题来体会一下。

Question

给定整数数组 nums 和一个目标元素 target ，请在数组里找两个加起来等于 target 的元素，返回它们的索引。返回任意一组解即可。

## 线性查找：以时间换空间

最直接的想法是把所有组合试一遍：如下图所示，开一个两层循环，每轮判断两个整数的和是不是 target ，是的话就返回它们的索引。

![线性查找求解两数之和](/genius/media/image_246.png)

代码如下所示：

```src

```

这种写法时间复杂度 $O(n^{2})$ 、空间复杂度 $O(1)$ ，数据量大时非常慢。

## 哈希查找：以空间换时间

换个思路，用一个哈希表，键值对分别是数组元素和元素索引。遍历数组，每轮做下图这几步。

1. 看看 target - nums[i] 在不在哈希表里，在的话直接返回这两个元素的索引。

1. 把键值对 nums[i] 和索引 i 存进哈希表。


这样用哈希查找把时间复杂度从 $O(n^{2})$ 降到 $O(n)$ ，运行效率提升很多。

由于需要维护一个额外的哈希表，因此空间复杂度为 $O(n)$ 。尽管如此，该方法的整体时空效率更为均衡，因此它是本题的最优解法。
