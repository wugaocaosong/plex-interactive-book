## 首批并行安排

1. A 从共同提交建立并推送整合分支，先发宿主/检索/导航接口小 PR；B 发学习记录适配约定；C 发运行器适配约定；D 先发题目/检索/复习卡 fixture 和验收矩阵。每份接口由消费方确认，定义字段、错误和版本，避免凭空猜实现。
2. A 做离线包与搜索；B 做复习与引用；C 做积木与拼图；D 做教学数据、脚本、独立审校和集成验收。A/B/C 可用隔离 fixture 开发，真实数据合入前不能标为交付。
3. 每个 PR 保持范围单一。A 顺序合入公共接口、内容数据、功能 PR；其他分支 merge 整合分支后继续开发，不强制推送重写已共享历史。package/锁文件逐项处理。
4. D 汇总三尺寸/两模式及学习闭环证据；各作者修复自身问题。A 运行最终完整回归、干净 clone 和 ZIP 解压验证，才发私有 v0.5。后续 v0.6/v0.7/v0.8 按对应职责继续。

不是平均分 5~6 个功能就等量：A 有整合与发布，D 首轮有较重教学内容/验收，B 的协作与 C 的多运行时均安排后期。每轮验收一个完整学习流程，不能把 22 项全塞进 v0.5。
